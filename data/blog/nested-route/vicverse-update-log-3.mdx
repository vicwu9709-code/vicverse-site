本次更新是 Vicverse 从 v4 进入 v5 的一次大改。

它不是新增一个页面，也不是简单换一套颜色，而是重新确认了网站的版本规则、首页结构、专题入口、部署链路和维护方式。

这一版的关键词是：

```text
Archive v4. Open v5.
```

---

## v4 归档

在开始改版之前，当前网站状态被保存为 v4。

本次建立了两个清晰的归档点：

```text
archive/v4-structure
v4-structure
```

其中 `archive/v4-structure` 是 GitHub 上的归档分支，`v4-structure` 是对应的 Git tag。

这样做的原因很简单：

新版本可以大胆前进，但旧版本不能消失在混乱里。

如果后续需要回看 v4 的结构、页面状态或部署前的内容，都可以直接从这个归档点恢复。

---

## v5 命名规则

本次改版使用了新的工作分支：

```text
v5-orange-current
```

这个名字保留了三个信息：

- `v5`：这是 Vicverse 的第五阶段
- `orange`：橙色仍然是网站最核心的视觉信号
- `current`：这是当前正在推进的主版本

之后如果继续做更大版本，可以沿用类似规则：

```text
v6-主题-current
archive/v6-主题
```

这样版本不会只是一串提交记录，而是能被人直接理解。

## 首页重做

v5 最大的变化是首页。

原来的 `/` 是一个进入页，用户需要再点击一次“进入 Vicverse”才能看到真正内容。

这次改版后，`/` 直接成为主首页。

首页现在包含：

- 橙色 v5 视觉标识
- 海洋图像背景
- Vicverse 核心定位
- 最新日志列表
- 四条主线入口
- 联系方式

`/home` 仍然保留，但现在会自动重定向到 `/`。

这样访问正式域名时，读者第一眼看到的就是 Vicverse 本体，而不是一个过场页。

---

## 四条主线

v5 将网站内容重新整理为四条主线：

- 水下机器人
- 游戏思考
- 音乐分析
- 换血记录

其中水下机器人是当前主线。

游戏、音乐和网站更新不再只是散落的内容，而是被放进同一个长期记录系统里。

这让 Vicverse 更像一个可以持续生长的个人空间，而不是普通博客模板。

---

## 专题页重构

原来的 Projects 页面还保留了模板内容，例如 Google 和 Time Machine。

这次已经全部清理。

新的专题页使用真实的 Vicverse 内容，并新增了统一的专题页组件：

```text
app/projects/TopicPage.tsx
```

水下机器人、游戏思考、音乐分析、换血记录都基于这个组件生成。

这减少了重复代码，也让专题页之间的结构保持一致。

---

## 橙色视觉系统

本次改版保留了我喜欢的橙色，并把它变成更明确的主视觉。

全站 primary 色从模板里的粉色系换成了橙色系。

导航、按钮、链接、标签、标题辅助信息和 hover 状态都开始围绕橙色展开。

黑色背景仍然保留，但 v5 不再只是简单的黑底白字。

它开始有了更明确的空间感、主题感和版本感。

## Git hook 修复

本次还修复了一个工程问题。

项目的 `.yarnrc.yml` 指向：

```text
.yarn/releases/yarn-3.6.1.cjs
```

但这个文件原本不存在。

这会导致 Git pre-commit hook 调用 `yarn` 时失败。

现在已经通过 Corepack 获取 Yarn 3.6.1，并将 release 文件提交到仓库中。

随后进一步确认，这个仓库实际使用的是 npm lockfile 工作流。

因此 lint-staged 的任务也改成了 npm 本地依赖调用：

```text
npm exec -- eslint --fix
npm exec -- prettier --write
```

以后提交时，hook 不再依赖全局 `yarn` 命令，也不会被 Yarn lockfile 问题卡住。

## 后续方向

v5 之后，Vicverse 的重点不是继续堆页面，而是继续强化几个方向：

- 让水下机器人专题逐渐有真正的学习路径
- 给游戏和音乐内容建立更稳定的写作格式
- 清理历史部署项目，降低维护混乱
- 继续把每次重要改版写成更新日志
- 让 README 成为真正能维护项目的文档

这次改版之后，Vicverse 不再只是一个能发布文章的网站。

它开始有自己的版本系统、视觉语言和内容结构。

From chaos to structure.
