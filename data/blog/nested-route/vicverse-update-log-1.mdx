本次更新标志着 Vicverse 第一次完成公网部署。

网站已完成 GitHub 仓库同步、Vercel 自动部署和自定义域名解析。

Vicverse 正式从本地原型转变为一个可以长期维护、持续更新的在线平台。

当前访问地址：

`vicverse.me`

---

## 本次更新内容

### 1. 完成网站部署链路

本次更新成功建立了以下部署流程：

本地项目 → GitHub 仓库 → Vercel 自动部署 → 自定义域名

这意味着后续网站更新不再依赖手动上传，而是可以通过 GitHub 推送自动完成部署。

---

### 2. 网站结构初步确定

Vicverse 当前从复杂视觉实验，收束为一个可以长期更新的个人日志系统。

当前网站核心结构为：

入口页 → 日志主页 → 文章详情页

这个结构不追求一次性完成全部功能，而是优先保证稳定、清晰、可持续更新。

---

### 3. 建立基础文章发布方式

当前网站采用 MDX 文件作为文章内容来源。

每篇文章对应一个 `.mdx` 文件，包含标题、日期、标签、草稿状态、摘要和正文内容。

这为后续发布关于水下机器人、游戏、音乐、个人思考和网站建设的内容提供了基础。

---

## 本次开发中遇到的问题

### 问题一：GitHub 与 Vercel 仓库关联混乱

在开发过程中，曾出现多个仓库和多个部署项目并存的情况。

这导致修改代码后，线上网站没有变化，也难以判断 Vercel 实际部署的是哪个项目。

### 解决方案

重新确认当前 GitHub 仓库与 Vercel 项目的对应关系，明确真正生效的部署源。

在此基础上，重新完成推送和部署验证，最终使网站可以正常通过域名访问。

---

### 问题二：本地修改后线上未更新

部分内容在本地已经修改，但线上页面没有同步变化。

### 解决方案

重新检查完整发布链路：

- 本地文件是否保存
- GitHub 是否成功提交和推送
- Vercel 是否触发自动构建
- 域名访问的是否是最新部署结果

通过逐步排查，确认了网站更新流程。

---

### 问题三：本地开发环境混乱

开发过程中曾同时存在多个 terminal 和运行进程，导致无法确认当前实际运行的是哪个开发环境。

### 解决方案

关闭多余进程，只保留一个明确的开发终端。

这样降低了调试复杂度，也减少了误判问题来源的可能。
